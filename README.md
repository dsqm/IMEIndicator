# IMEIndicator

在文本光标左下角显示一个小圆点，用来提示当前输入法状态：英文 / 中文 / 大写 / 英文键盘 / 日文 / 韩文。
纯 Win32，无依赖，单个 exe。

## 构建

需要 Visual Studio（MSVC x64）：

```
build.bat
```

产物在 `bin\IMEIndicator.exe`。许可证 GPL-3.0-or-later，见 `LICENSE`。

## 运行

把 `IMEIndicator.exe` 放到想要的位置，双击运行 —— 只在托盘显示一个字母 `I` 图标，没有主窗口。

托盘图标悬停提示为 `IMEIndicator`；**以管理员运行时**显示为 `IMEIndicator（管理员）`

托盘右键菜单：

| 菜单项 | 说明 |
|---|---|
| 记录日志 | 开/关调试日志，写到 `<exe 目录>\log\IMEIndicator-<时间>.log` |
| 打开配置 | 用记事本打开 `IMEIndicator.ini`（改完点「重启」生效） |
| 重启 | 重新加载配置 |
| 退出 | 退出程序 |

启动参数：

- `--log` —— 启动即开日志（排查问题时不用先去点托盘菜单）

同一时刻只允许一个实例，重复启动会直接退出。

## 配置

首次运行会在 exe 同目录生成带注释的 `IMEIndicator.ini`（UTF-8）。要点：

- 颜色固定 `#RRGGBB`；透明度统一用 `Alpha`，颜色值不带 AA
- 色值写 `0` = 该状态**不显示**圆点（默认 `Cn = 0`，即中文态无圆点）
- `0` 不等于黑色 —— 黑色写 `#000000`
- 改完必须重启才生效

状态判定：

| 状态 | 判据 | 默认颜色 |
|---|---|---|
| Caps | Caps Lock 打开 | 蓝 `#0080FF` |
| KbdEn | 键盘布局主语言为英文（0x09） | 紫 `#8B00FF` |
| Jp | 主语言日文（0x11） | 黑 `#000000` |
| Kr | 主语言韩文（0x12） | 黑 `#000000` |
| Cn / En | 其余布局走 IME 中英判定 | 不显示 / 红 `#FF0000` |

- `HideWhenFullscreen = 1` —— 前景窗口全屏时不显示圆点（看视频/演示不遮挡）
- `CaretTimeoutMs = 150` —— 单次光标查询最长等待（毫秒），见下
- `Shape = circle` —— 圆点形状：`circle`（圆，默认）或 `triangle`（等边三角形，尖角朝上）。
  两种形状按同一个 `Size` 计算大小，换形状不用重新调尺寸

### 光标查询的超时保护

光标位置要**跨进程**问 UIA/MSAA，而这些调用**没有超时参数**：前台程序（浏览器、
Electron 应用）线程一卡，调用就悬着不返回，检测线程跟着冻住数秒，日志心跳整段断掉。

所以查询放在**独立线程**里做，检测线程只按 `CaretTimeoutMs` 等事件：

- 正常：拿到本轮坐标
- 超时：放弃本轮查询，**沿用上一轮的显示状态**（而不是让圆点闪一下消失），
  日志记一行 `caret: query timeout >150ms (foreground app busy)`，
  状态行里 `to=1`
- **连续超时 20 次（约 3 秒）**：判定查询线程已永久卡死在某个跨进程调用里
  （个别程序被挂起时调用永不返回），自动换一代查询线程重新开工，日志记
  `caret: worker stuck (20 consecutive timeouts) -- respawning`。不这样
  做的话，圆点会从此不再显示，只能重启程序
- 程序退出时不再等待查询线程（它最多多活 1 秒）

## 什么时候不显示圆点

- 当前状态的颜色配成 `0`（默认 `Cn = 0`，中文态无圆点）
- **取不到真实光标**：焦点不在文本输入处时，MSAA 会报出"上一次出现过的光标位置"，
  那种过期坐标不算数。UIA 的 `GetCaretRange` 会给出 `isActive`，程序据此判定"到底
  有没有活动光标"，为否就不显示
- **前景窗口全屏**（无标题栏且尺寸 ≥ 显示器 98%）
- **刚切换窗口后的约 0.2 秒**（见下）
- 光标坐标离前台窗口太远（各通道的合理性过滤）

### 切换窗口时为什么要短暂隐藏

切窗口后向 IME 问到的**仍是上一个窗口的值**（实测滞后 200~300ms）。如果这期间照旧
显示，就会看到"从英文窗口切走时先亮一个红点、随即消失"的闪烁。

所以程序在切窗口后把圆点收起来，等读数稳定（`IME_SETTLE_MS`，200ms）再按真实状态
显示。代价是从一个英文窗口切到另一个英文窗口时，圆点会缺席约 0.2 秒 —— 相比"先亮
错颜色"，短暂没有点更不容易误导。

日志里能看到这段过程：`settle: arm` / `settle: release held=219 ms`，
以及每行状态里的 `gate=1`（该拍被收起）。

> 本程序不需要管理员权限。但**非管理员时读不到管理员程序的输入法状态** ——
> UIPI 会拦掉跨进程消息且无任何报错（现象是"在某些程序里圆点不跟随"）。
> 命中时日志会记一行 `UIPI: 目标程序以更高权限运行…`，按需以管理员启动即可。

中英判定同时取 `IMC_GETOPENSTATUS` 与 `IMC_GETCONVERSIONMODE`，
观察切换时哪个信号在变来选定权威信号（不同输入法暴露的开关不一样），
信号需稳定 200ms 才采纳。识别不准时可在 ini 里用 `ImeStrategy = 1`（只看 open 状态）
或 `2`（只看转换模式）手动指定。
